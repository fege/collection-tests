# TC-E2E-001: Full upgrade journey — pre-3.3 to 3.3 with route migration verification

**Objective**: End-to-end validation that a user with a pre-3.3 RHOAI deployment can upgrade to 3.3 and access the dashboard without disruption, covering both old and new routes.

**Preconditions**:
- OpenShift cluster running RHOAI pre-3.3 with dashboard fully operational
- Dashboard accessible at the old `rhods-dashboard-redhat-ods-applications` route
- Authenticated user with dashboard access and cluster-admin for upgrade

**Test Steps**:
1. **Pre-upgrade baseline**: Access the dashboard at the old route and verify it loads:
   ```bash
   OLD_ROUTE=$(oc get route rhods-dashboard -n redhat-ods-applications -o jsonpath='{.spec.host}')
   curl -sSL -o /dev/null -w "%{http_code}" -H "Authorization: Bearer $(oc whoami -t)" "https://${OLD_ROUTE}"
   ```
   Expected: HTTP 200
2. **Record pre-upgrade state**: Note the route name, hostname, and target service:
   ```bash
   oc get route rhods-dashboard -n redhat-ods-applications -o jsonpath='name={.metadata.name} host={.spec.host} service={.spec.to.name}'
   ```
3. **Initiate upgrade**: Update the RHOAI operator subscription to the 3.3 channel and wait for completion:
   ```bash
   oc get csv -n redhat-ods-operator --watch
   ```
4. **Wait for stabilization**: Verify all pods are running and ready:
   ```bash
   oc get pods -n redhat-ods-applications -o wide
   ```
5. **Verify new route exists**: Confirm the `data-science-gateway` route is created:
   ```bash
   NEW_ROUTE=$(oc get route -n redhat-ods-applications -o jsonpath='{range .items[*]}{.spec.host}{"\n"}{end}' | grep data-science-gateway)
   echo "New route: https://${NEW_ROUTE}"
   ```
6. **Access new route**: Navigate to the new route and verify dashboard loads:
   ```bash
   curl -sSL -o /dev/null -w "%{http_code}" -H "Authorization: Bearer $(oc whoami -t)" "https://${NEW_ROUTE}"
   ```
   Expected: HTTP 200
7. **Access old route**: Navigate to the old route URL and verify user is not stranded:
   ```bash
   curl -sSL -D - -H "Authorization: Bearer $(oc whoami -t)" "https://${OLD_ROUTE}" -o /dev/null
   ```
   Expected: redirect, informational page, or dashboard — NOT 401/403
8. **Browser verification**: Open the new route in a browser, complete login, verify the dashboard UI renders with sidebar, header, and main content

**Expected Results**:
- Pre-upgrade: dashboard accessible at old route (HTTP 200)
- Post-upgrade: new `data-science-gateway` route exists and serves the dashboard (HTTP 200)
- Post-upgrade: old route does not strand users with "Unauthorized" or loading errors
- Dashboard UI renders fully in the browser on the new route
- The complete upgrade journey succeeds without manual route discovery
