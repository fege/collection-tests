# TC-E2E-002: Bookmarked URL continuity journey after upgrade

**Objective**: End-to-end validation that a user who bookmarked the old dashboard URL before upgrade can reach the dashboard after upgrade without manual route discovery.

**Preconditions**:
- OpenShift cluster running RHOAI pre-3.3 with dashboard operational
- Old dashboard route URL "bookmarked" (recorded) before upgrade
- RHOAI upgrade to 3.3 completed

**Test Steps**:
1. **Before upgrade**: Record the dashboard URL as a "bookmark":
   ```bash
   BOOKMARK="https://$(oc get route rhods-dashboard -n redhat-ods-applications -o jsonpath='{.spec.host}')"
   echo "Bookmarked URL: ${BOOKMARK}"
   ```
2. **Complete the upgrade** to RHOAI 3.3
3. **Simulate bookmark access**: Open the bookmarked URL in a new browser session (clear cookies/cache to simulate a fresh visit):
   ```bash
   curl -sSL -D - -o /dev/null "${BOOKMARK}"
   ```
4. **Follow any redirects or instructions**: If redirected, follow the chain to the final destination. If an informational page is shown, follow the provided link
5. **Verify arrival at dashboard**: Confirm the user reaches the RHOAI dashboard at the new `data-science-gateway` route
6. **Test authenticated bookmark access**: Access the bookmarked URL with valid credentials:
   ```bash
   curl -sSL -D - -H "Authorization: Bearer $(oc whoami -t)" "${BOOKMARK}" -o /dev/null
   ```
7. **Browser test**: Open the bookmarked URL in a browser, complete login if prompted, verify dashboard loads

**Expected Results**:
- The bookmarked old URL does NOT result in "Unauthorized" errors or infinite loading
- The user is guided to the new dashboard location through the implemented access-continuity mechanism
- The user ultimately reaches a working RHOAI dashboard at the `data-science-gateway` route
- The journey from bookmark to working dashboard requires no manual OpenShift console navigation to discover the new route
- This directly validates the resolution of the user experience issue described in RHOAIENG-48787
