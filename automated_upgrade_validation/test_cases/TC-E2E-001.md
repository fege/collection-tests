# TC-E2E-001: Full upgrade validation cycle for supported upgrade path

**Objective**: Verify the complete end-to-end upgrade validation pipeline for a single supported upgrade path, covering all pipeline steps from cluster provisioning through result publication.

**Preconditions**:
- CI pipeline infrastructure is available
- At least one supported upgrade path is configured (e.g., 2.25.6→3.5)
- Component and cross-component scenario manifests are available
- Results publication system is configured

**Test Steps**:
1. Trigger upgrade validation for a supported upgrade path (e.g., RHOAI 2.25.6→3.5)
2. Verify the pipeline provisions a cluster at the pre-upgrade version (2.25.6)
3. Verify component-owned scenarios are deployed as pre-upgrade baselines
4. Verify cross-component scenarios are deployed as pre-upgrade baselines
5. Verify pre-upgrade checks execute and prerequisites are resolved
6. Verify the platform upgrade executes from 2.25.6 to 3.5
7. Verify post-upgrade steps execute successfully
8. Verify component-owned scenario validation passes (workloads functional post-upgrade)
9. Verify cross-component workflow validation passes (workflows survive upgrade)
10. Verify workload continuity and data-plane impact are measured (not just operator convergence)
11. Verify results are published automatically with failure attribution
12. Verify the release-readiness gate reflects the validation outcome

**Expected Results**:
- All pipeline steps complete in sequence without manual intervention
- Component workloads deployed pre-upgrade remain functional post-upgrade
- Cross-component workflows deployed pre-upgrade survive the upgrade
- Data-plane endpoints respond correctly post-upgrade
- Results are published and visible to release engineering and component teams
- The release-readiness gate reflects PASS for this upgrade path
- Total pipeline execution time is within acceptable bounds
