# TC-E2E-002: Disconnected mode upgrade validation cycle

**Objective**: Verify the end-to-end upgrade validation pipeline executes successfully in disconnected mode, where the cluster cannot access external registries or the internet during upgrade.

**Preconditions**:
- Disconnected mode cluster infrastructure is available
- Image mirroring is configured for pre-upgrade and post-upgrade versions
- Local registry contains all required images and catalog sources

**Test Steps**:
1. Provision a disconnected cluster at the pre-upgrade RHOAI version
2. Deploy component and cross-component scenarios using mirrored images
3. Execute pre-upgrade checks in disconnected mode
4. Execute the platform upgrade using mirrored operator catalog
5. Execute post-upgrade steps
6. Validate component and cross-component scenarios post-upgrade
7. Verify results are published

**Expected Results**:
- The pipeline completes all steps without requiring external network access
- Component and cross-component scenarios pass validation in disconnected mode
- No image pull failures from external registries during upgrade
- Results are published with the same quality as connected mode runs
