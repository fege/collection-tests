# TC-E2E-003: Multi-path upgrade matrix validation with mixed results

**Objective**: Verify that the pipeline correctly handles a multi-path validation run where some upgrade paths pass and others fail, with correct attribution and gate behavior.

**Preconditions**:
- Upgrade matrix contains at least two upgrade paths
- One path is expected to pass, one is expected to fail (e.g., a component scenario fails on one path)
- Results publication and release-readiness gate are configured

**Test Steps**:
1. Trigger upgrade validation for a release artifact with multiple upgrade paths in the matrix
2. Allow path A to complete successfully (all scenarios pass)
3. Allow path B to have a component scenario failure
4. Verify results are published for both paths
5. Check the release-readiness gate status

**Expected Results**:
- Path A results are published as PASS
- Path B results are published as FAIL with correct component attribution
- The release-readiness gate reports FAIL (at least one path failed)
- Each path's results are independent — path A success does not mask path B failure
- The gate failure message identifies path B as the failing path
