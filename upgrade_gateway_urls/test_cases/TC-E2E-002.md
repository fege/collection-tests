# TC-E2E-002: Migration journey — upgrade, migrate workbench, verify Gateway URLs

**Objective**: Validate the complete migration path for a workbench post-upgrade: verify pre-migration Route access, confirm Service and HTTPRoute configuration, migrate to inject-auth, and verify Gateway URL becomes functional in both CLI and Dashboard.

**Preconditions**:
- RHOAI 3.3 installed (post-upgrade from 2.25)
- JupyterLab workbench `jupyter-wb` is running in namespace `upgrade-url-test`
- Workbench has not been migrated (no `inject-auth: true` annotation)

**Test Steps**:
1. Verify the workbench is accessible via its legacy Route URL:
   ```bash
   JP_ROUTE=$(oc get route jupyter-wb -n upgrade-url-test -o jsonpath='{.spec.host}')
   curl -kL -o /dev/null -s -w "%{http_code}" https://${JP_ROUTE}/notebook/upgrade-url-test/jupyter-wb
   ```
2. Verify the Service port configuration:
   ```bash
   oc get service jupyter-wb -n upgrade-url-test \
     -o jsonpath='{range .spec.ports[*]}port={.port} targetPort={.targetPort}{"\n"}{end}'
   ```
3. Verify the HTTPRoute exists and check its backend port:
   ```bash
   oc get httproute -n upgrade-url-test -l notebook-name=jupyter-wb \
     -o jsonpath='{.items[0].spec.rules[0].backendRefs[0].port}'
   ```
4. Migrate the workbench:
   ```bash
   oc annotate notebook jupyter-wb -n upgrade-url-test inject-auth=true
   ```
5. Wait for the controller to reconcile (up to 60 seconds).
6. Retrieve the updated Gateway URL:
   ```bash
   JP_GW=$(oc get httproute -n upgrade-url-test -l notebook-name=jupyter-wb \
     -o jsonpath='{.items[0].spec.hostnames[0]}')
   ```
7. Access the Gateway URL:
   ```bash
   curl -kL -o /dev/null -s -w "%{http_code}" https://${JP_GW}/notebook/upgrade-url-test/jupyter-wb
   ```
8. Navigate to the Dashboard > `upgrade-url-test` > Workbenches tab and verify the URL displayed for `jupyter-wb`.

**Expected Results**:
- Step 1: Route URL returns HTTP `200`
- Step 2: Service port is `80` with targetPort `8888`
- Step 3: HTTPRoute backend port is `80` (not `8888`)
- Step 4: Annotation command completes without error
- Step 6: A Gateway hostname is returned (not empty)
- Step 7: Gateway URL returns HTTP `200`
- Step 8: Dashboard displays a URL for `jupyter-wb` that differs from the Route URL used in Step 1
