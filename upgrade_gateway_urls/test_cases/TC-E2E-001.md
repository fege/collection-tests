# TC-E2E-001: Full upgrade journey — pre-upgrade baseline and post-upgrade workbench accessibility

**Objective**: Validate the complete upgrade path from RHOAI 2.25 to 3.3 by establishing pre-upgrade accessibility baselines for all workbench types and verifying they remain accessible via legacy Route URLs post-upgrade.

**Preconditions**:
- RHOAI cluster with workbenches created in RHOAI 2.25 (pre-upgrade phase) or already upgraded to 3.3 (post-upgrade phase)
- Namespace `upgrade-url-test` contains running workbenches: `jupyter-wb` (JupyterLab), `codeserver-wb` (Code-server), `rstudio-wb` (RStudio)
- All workbenches are unmigrated (no `inject-auth: true` annotation)

**Test Steps**:
1. Retrieve Route hostnames for all workbenches:
   ```bash
   CS_HOST=$(oc get route codeserver-wb -n upgrade-url-test -o jsonpath='{.spec.host}')
   JP_HOST=$(oc get route jupyter-wb -n upgrade-url-test -o jsonpath='{.spec.host}')
   RS_HOST=$(oc get route rstudio-wb -n upgrade-url-test -o jsonpath='{.spec.host}')
   ```
2. Verify each workbench is accessible via its Route URL:
   ```bash
   curl -kL -o /dev/null -s -w "%{http_code}" https://${CS_HOST}/
   curl -kL -o /dev/null -s -w "%{http_code}" https://${JP_HOST}/notebook/upgrade-url-test/jupyter-wb
   curl -kL -o /dev/null -s -w "%{http_code}" https://${RS_HOST}/
   ```
3. Navigate to the RHOAI Dashboard > Data Science Projects > `upgrade-url-test` > Workbenches tab.
4. Verify all three workbenches display status "Running" and have clickable URL links.
5. Click each workbench URL in the Dashboard and verify the application loads.

**Expected Results**:
- All three Route URLs return HTTP `200` (Step 2)
- The Dashboard Workbenches tab lists all three workbenches with "Running" status
- Each workbench row in the Dashboard displays a clickable URL link
- Clicking each Dashboard URL opens a new browser tab that does not display an HTTP error page (no "500 Internal Server Error", no "Application is not available")
- No URL access results in an HTTP 500 error page
