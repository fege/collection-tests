# TC-E2E-003: Mixed-state cluster — all workbench types and migration states

**Objective**: Validate that a cluster with all three workbench types in different migration states provides correct URL access for each through both CLI and Dashboard.

**Preconditions**:
- RHOAI cluster with workbenches created in RHOAI 2.25 (pre-upgrade) or already upgraded to 3.3 (post-upgrade)
- Namespace `upgrade-url-test` contains:
  - `codeserver-wb` (Code-server): unmigrated
  - `jupyter-wb` (JupyterLab): migrated with `inject-auth: true` (post-upgrade only; unmigrated in pre-upgrade)
  - `rstudio-wb` (RStudio): unmigrated
- All workbenches are running

**Test Steps**:
1. Verify the migration state of each workbench:
   ```bash
   for WB in codeserver-wb jupyter-wb rstudio-wb; do
     echo "$WB: $(oc get notebook $WB -n upgrade-url-test -o jsonpath='{.metadata.annotations.inject-auth}')"
   done
   ```
2. Access each unmigrated workbench via its Route URL:
   ```bash
   CS_HOST=$(oc get route codeserver-wb -n upgrade-url-test -o jsonpath='{.spec.host}')
   curl -kL -o /dev/null -s -w "%{http_code}" https://${CS_HOST}/

   RS_HOST=$(oc get route rstudio-wb -n upgrade-url-test -o jsonpath='{.spec.host}')
   curl -kL -o /dev/null -s -w "%{http_code}" https://${RS_HOST}/
   ```
3. Access the migrated workbench via its appropriate URL (Gateway post-upgrade, Route pre-upgrade):
   ```bash
   # Post-upgrade: use Gateway URL
   JP_GW=$(oc get httproute -n upgrade-url-test -l notebook-name=jupyter-wb \
     -o jsonpath='{.items[0].spec.hostnames[0]}' 2>/dev/null)
   if [ -n "$JP_GW" ]; then
     curl -kL -o /dev/null -s -w "%{http_code}" https://${JP_GW}/notebook/upgrade-url-test/jupyter-wb
   fi

   # Pre-upgrade fallback: use Route URL
   JP_ROUTE=$(oc get route jupyter-wb -n upgrade-url-test -o jsonpath='{.spec.host}')
   curl -kL -o /dev/null -s -w "%{http_code}" https://${JP_ROUTE}/notebook/upgrade-url-test/jupyter-wb
   ```
4. Navigate to the Dashboard > `upgrade-url-test` > Workbenches tab.
5. Verify each workbench has a clickable URL link and click each one.

**Expected Results**:
- Step 1: `codeserver-wb` and `rstudio-wb` show no `inject-auth` value; `jupyter-wb` shows `true` (post-upgrade) or no value (pre-upgrade)
- Step 2: Both unmigrated workbench Route URLs return HTTP `200`
- Step 3: Migrated workbench URL returns HTTP `200` (Gateway URL post-upgrade, Route URL pre-upgrade)
- Step 5: All three workbenches in the Dashboard have clickable URLs; clicking each opens a browser tab that does not display an HTTP error page (no "500 Internal Server Error", no "Application is not available")
