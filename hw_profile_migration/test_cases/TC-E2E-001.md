# TC-E2E-001: Full migration lifecycle from accelerator profile to hardware profile

**Objective**: End-to-end validation of the complete migration lifecycle: create accelerator profile, create notebook using it, trigger operator upgrade, verify hardware profile creation, verify both annotations are set, verify webhook accepts the migrated notebook, and verify operator stability.

**Preconditions**:
- OpenShift cluster with RHOAI operator installed (pre-upgrade version that uses accelerator profiles)
- User namespace `e2e-migration-project` created
- Cluster admin access for operator upgrade

**Test Steps**:
1. Create an accelerator profile in the global namespace:
   ```bash
   oc apply -f - <<EOF
   apiVersion: dashboard.opendatahub.io/v1alpha1
   kind: AcceleratorProfile
   metadata:
     name: e2e-test-gpu-accel
     namespace: redhat-ods-applications
   spec:
     displayName: "E2E Test GPU Accelerator"
     enabled: true
     identifier: nvidia.com/gpu
     tolerations:
     - effect: NoSchedule
       key: nvidia.com/gpu
       operator: Exists
   EOF
   ```
2. Create a notebook that uses the accelerator profile:
   ```bash
   oc apply -f - <<EOF
   apiVersion: kubeflow.org/v1
   kind: Notebook
   metadata:
     name: e2e-test-workbench
     namespace: e2e-migration-project
     annotations:
       opendatahub.io/accelerator-name: e2e-test-gpu-accel
   spec:
     template:
       spec:
         containers:
         - name: notebook
           image: quay.io/opendatahub/notebooks:jupyter-minimal
           resources:
             limits:
               nvidia.com/gpu: "1"
   EOF
   ```
3. Verify notebook is running with accelerator profile reference:
   ```bash
   oc get notebook e2e-test-workbench -n e2e-migration-project \
     -o jsonpath='{.metadata.annotations.opendatahub\.io/accelerator-name}'
   ```
4. Record operator pod state before upgrade:
   ```bash
   oc get pods -l name=rhods-operator -n redhat-ods-operator \
     -o jsonpath='{.items[0].status.containerStatuses[0].restartCount}'
   ```
5. Trigger the operator upgrade to RHOAI 3.3 (with the fix)
6. Wait for the upgrade to complete and operator to stabilize (Running state, max 10 min)
7. Verify hardware profile was created in global namespace:
   ```bash
   oc get hardwareprofile -n redhat-ods-applications | grep e2e-test-gpu-accel
   ```
8. Verify both annotations are on the notebook:
   ```bash
   oc get notebook e2e-test-workbench -n e2e-migration-project \
     -o jsonpath='{.metadata.annotations.opendatahub\.io/hardware-profile-name}'
   oc get notebook e2e-test-workbench -n e2e-migration-project \
     -o jsonpath='{.metadata.annotations.opendatahub\.io/hardware-profile-namespace}'
   ```
9. Verify namespace annotation points to global namespace (not notebook namespace):
   ```bash
   NAMESPACE=$(oc get notebook e2e-test-workbench -n e2e-migration-project \
     -o jsonpath='{.metadata.annotations.opendatahub\.io/hardware-profile-namespace}')
   [ "$NAMESPACE" = "redhat-ods-applications" ] && echo "PASS" || echo "FAIL: namespace is $NAMESPACE"
   ```
10. Verify operator did not crashloop:
    ```bash
    RESTARTS=$(oc get pods -l name=rhods-operator -n redhat-ods-operator \
      -o jsonpath='{.items[0].status.containerStatuses[0].restartCount}')
    echo "Restart count: $RESTARTS"
    ```
11. Verify no error logs from migration:
    ```bash
    oc logs -l name=rhods-operator -n redhat-ods-operator --tail=200 | grep -c "failed to set HardwareProfile"
    ```

**Expected Results**:
- Hardware profile CR is created in `redhat-ods-applications` with name derived from `e2e-test-gpu-accel`
- Notebook has `opendatahub.io/hardware-profile-name` annotation set to the new hardware profile name
- Notebook has `opendatahub.io/hardware-profile-namespace` set to `redhat-ods-applications`
- Operator pod restart count increased by at most 1 (for the upgrade itself)
- Zero `failed to set HardwareProfile` errors in operator logs
- Notebook remains functional after migration
