# TC-E2E-001: Full tool calling round-trip with Qwen/Qwen3-235B-A22B-GPTQ-Int4

**Objective**: Validate the complete user journey: read the model card, copy-paste the vllm serve command, deploy the model, and execute a successful tool calling round-trip with Qwen3-235B-A22B-GPTQ-Int4.

**Preconditions**:
- Qwen/Qwen3-235B-A22B-GPTQ-Int4 model weights are available on storage accessible from the cluster
- GPU hardware meets minimum requirements: 4x A100 80GB (320 GB total VRAM)
- Red Hat AI Inference Server version matches the version documented in the model card

**Test Steps**:
1. Open the Qwen/Qwen3-235B-A22B-GPTQ-Int4 model card from the model-metadata-collection repository
2. Locate the "Tool Calling Configuration" section
3. Copy the documented `vllm serve` command (including `--tool-call-parser`, `--reasoning-parser`, `--chat-template`, `--enable-auto-tool-choice`)
4. Deploy the model using the copy-pasted command (via ServingRuntime/InferenceService CR or direct CLI)
5. Wait for vLLM to reach ready state (verify via `GET /v1/models`)
6. Send a tool calling request:
   ```json
   {
     "model": "Qwen/Qwen3-235B-A22B-GPTQ-Int4",
     "messages": [{"role": "user", "content": "What is the weather in Boston today?"}],
     "tools": [
       {
         "type": "function",
         "function": {
           "name": "get_weather",
           "description": "Get the current weather for a location",
           "parameters": {"type": "object", "properties": {"location": {"type": "string", "description": "City and state"}}, "required": ["location"]}
         }
       }
     ],
     "tool_choice": "auto"
   }
   ```
7. Validate the response contains a valid `tool_calls` array
8. Submit the tool result back to the model:
   ```json
   {
     "model": "Qwen/Qwen3-235B-A22B-GPTQ-Int4",
     "messages": [
       {"role": "user", "content": "What is the weather in Boston today?"},
       {"role": "assistant", "content": null, "tool_calls": [{"id": "<call-id>", "type": "function", "function": {"name": "get_weather", "arguments": "{\"location\": \"Boston, MA\"}"}}]},
       {"role": "tool", "tool_call_id": "<call-id>", "content": "{\"temperature\": 72, \"unit\": \"fahrenheit\", \"condition\": \"sunny\"}"}
     ],
     "tools": [...]
   }
   ```
9. Verify the model produces a natural language response incorporating the tool result

**Expected Results**:
- vLLM starts successfully with the copy-pasted command on first attempt
- Tool calling request returns a valid `tool_calls` array with `function.name` matching `get_weather` and valid JSON `arguments`
- `finish_reason` is `"tool_calls"`
- Tool response round-trip completes: model produces a coherent reply incorporating the weather data (e.g., mentions "72 degrees" or "sunny")
- No parsing errors, no empty `tool_calls` arrays, no silent failures
