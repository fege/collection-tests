# TC-E2E-002: Full tool calling round-trip with openai/gpt-oss-120b

**Objective**: Validate the complete user journey: read the model card, copy-paste the vllm serve command, deploy the model, and execute a successful tool calling round-trip with gpt-oss-120b.

**Preconditions**:
- openai/gpt-oss-120b model weights are available on storage accessible from the cluster
- GPU hardware meets minimum requirements as specified by PSAP hardware validation docs
- Red Hat AI Inference Server version matches the version documented in the model card

**Test Steps**:
1. Open the openai/gpt-oss-120b model card from the model-metadata-collection repository
2. Locate the "Tool Calling Configuration" section
3. Copy the documented `vllm serve` command
4. Deploy the model using the copy-pasted command
5. Wait for vLLM to reach ready state (verify via `GET /v1/models`)
6. Send a tool calling request with a function tool:
   ```json
   {
     "model": "openai/gpt-oss-120b",
     "messages": [{"role": "user", "content": "Convert 100 USD to EUR"}],
     "tools": [
       {
         "type": "function",
         "function": {
           "name": "convert_currency",
           "description": "Convert an amount from one currency to another",
           "parameters": {"type": "object", "properties": {"amount": {"type": "number"}, "from_currency": {"type": "string"}, "to_currency": {"type": "string"}}, "required": ["amount", "from_currency", "to_currency"]}
         }
       }
     ],
     "tool_choice": "auto"
   }
   ```
7. Validate the response contains a valid `tool_calls` array with `function.name` = `convert_currency`
8. Submit a tool result and verify the model produces a natural language response

**Expected Results**:
- vLLM starts successfully with the documented command
- Tool calling request returns valid `tool_calls` with correct function name and parseable JSON arguments
- `finish_reason` is `"tool_calls"`
- Full round-trip completes with coherent model response incorporating tool result
- No `KeyError`, no streaming crash (ref: upstream #36849), no parsing failures
