# TC-E2E-008: Verify tool calling round-trip with streaming enabled

**Objective**: Confirm that tool calling works correctly when using streaming responses (`"stream": true`), since streaming with the wrong parser has been a known failure mode (ref: upstream #36849 GPT-OSS streaming crash).

**Preconditions**:
- At least one in-scope model is deployed with its validated configuration

**Test Steps**:
1. Send a tool calling request with streaming enabled:
   ```json
   {
     "model": "<model-name>",
     "messages": [{"role": "user", "content": "What is the weather in Boston today?"}],
     "tools": [
       {
         "type": "function",
         "function": {
           "name": "get_weather",
           "description": "Get the current weather for a location",
           "parameters": {"type": "object", "properties": {"location": {"type": "string"}}, "required": ["location"]}
         }
       }
     ],
     "tool_choice": "auto",
     "stream": true
   }
   ```
2. Collect all streamed chunks and reconstruct the complete response
3. Validate that the reconstructed response contains a valid `tool_calls` array
4. Verify no server errors or crashes occur during streaming

**Expected Results**:
- Streaming response completes without errors or crashes
- Reconstructed tool_calls from streamed chunks produce valid function name and arguments
- No `finish_reason` inconsistencies between streamed chunks
- Server remains healthy after the streaming request completes
