# TC-E2E-003: Full tool calling round-trip with nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-NVFP4

**Objective**: Validate a complete tool calling round-trip using the `servingConfig.toolCalling` values for nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-NVFP4: deploy with servingConfig values, send a tool call request, verify the response, submit a tool result, and verify natural language continuation.

**Preconditions**:
- nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-NVFP4 model weights are available on storage accessible from the cluster
- GPU hardware meets minimum requirements for this model
- Red Hat AI Inference Server version matches the version targeted by the servingConfig

**Test Steps**:
1. Extract `servingConfig.toolCalling` values for nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-NVFP4 from the CatalogModel
2. Deploy the model using the extracted configuration:
   ```bash
   vllm serve nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-NVFP4 \
     --tool-call-parser=<toolCallParser> \
     --chat-template=<chatTemplate> \
     --enable-auto-tool-choice \
     <requiredArgs if present>
   ```
3. Wait for vLLM to reach ready state (verify via `GET /v1/models`)
4. Send a tool calling request:
   ```json
   {
     "model": "nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-NVFP4",
     "messages": [{"role": "user", "content": "What is the weather in Boston today?"}],
     "tools": [{"type": "function", "function": {"name": "get_weather", "description": "Get the current weather for a location", "parameters": {"type": "object", "properties": {"location": {"type": "string"}}, "required": ["location"]}}}],
     "tool_choice": "auto"
   }
   ```
5. Validate the response contains a valid `tool_calls` array with `function.name` = `get_weather`
6. Submit the tool result back to the model:
   ```json
   {
     "model": "nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-NVFP4",
     "messages": [
       {"role": "user", "content": "What is the weather in Boston today?"},
       {"role": "assistant", "content": null, "tool_calls": [{"id": "<call-id>", "type": "function", "function": {"name": "get_weather", "arguments": "{\"location\": \"Boston, MA\"}"}}]},
       {"role": "tool", "tool_call_id": "<call-id>", "content": "{\"temperature\": 72, \"unit\": \"fahrenheit\", \"condition\": \"sunny\"}"}
     ],
     "tools": [{"type": "function", "function": {"name": "get_weather", "description": "Get the current weather for a location", "parameters": {"type": "object", "properties": {"location": {"type": "string"}}, "required": ["location"]}}}]
   }
   ```
7. Verify the model produces a natural language response incorporating the tool result

**Expected Results**:
- vLLM starts successfully with the servingConfig values
- Tool calling request returns a valid `tool_calls` array with `function.name` = `get_weather` and valid JSON `arguments`
- `finish_reason` is `"tool_calls"`
- Tool response round-trip completes: model produces a coherent reply incorporating the weather data
- No parsing errors, no empty `tool_calls` arrays, no silent failures
