# TC-E2E-003: Deploy EvalHub → delete EvalHub → ServiceMonitor cleaned up

**Objective**: Validate the complete lifecycle: deploying an EvalHub instance creates monitoring resources, and deleting it cleans everything up via Kubernetes garbage collection.

**Preconditions**:
- OpenShift cluster with RHOAI 3.5.EA1 and TrustyAI operator
- No existing EvalHub instances in the test namespace

**Test Steps**:
1. Deploy an EvalHub CR with metrics enabled
   ```bash
   oc apply -f evalhub-metrics-enabled.yaml -n opendatahub
   ```
2. Wait for ServiceMonitor creation and Prometheus scraping to begin
   ```bash
   oc wait --for=condition=Ready pod -l app=evalhub -n opendatahub --timeout=120s
   ```
3. Record all monitoring resources created
   ```bash
   oc get servicemonitor -n opendatahub -l app=evalhub -o name
   oc get networkpolicy -n opendatahub | grep evalhub
   ```
4. Delete the EvalHub CR
   ```bash
   oc delete evalhub evalhub-test -n opendatahub
   ```
5. Wait for Kubernetes garbage collection (up to 60 seconds)
6. Verify ServiceMonitor is removed
   ```bash
   oc get servicemonitor -n opendatahub -l app=evalhub 2>&1
   ```
7. Verify Prometheus no longer lists EvalHub as a scrape target
   ```bash
   oc exec -n openshift-user-workload-monitoring prometheus-user-workload-0 -c prometheus -- \
     curl -s 'http://localhost:9090/api/v1/targets' | jq '.data.activeTargets[] | select(.labels.job | contains("evalhub"))'
   ```

**Expected Results**:
- After EvalHub CR deletion, the ServiceMonitor is automatically removed via ownerReference GC
- Prometheus no longer lists EvalHub as an active scrape target
- No orphaned monitoring resources remain in the namespace
