# TC-E2E-003: CI/CD pipeline consumes artifact URIs from job status for automated report retrieval

**Objective**: Validate that a CI/CD pipeline can programmatically retrieve published evaluation reports using artifact URIs from the job status response, without manual path construction.

**Preconditions**:
- Full EvalHub deployment with completed evaluation job
- Script simulating CI/CD pipeline artifact retrieval

**Test Steps**:
1. Submit an evaluation job and wait for `Complete` status
2. Query GET /api/v1/evaluations/jobs/{id} to get the artifact URIs
3. For each artifact URI in the response, programmatically call GET /get-artifact?run_id={run_id}&path={artifact_path}
4. Save the retrieved artifacts locally
5. Verify each artifact was successfully downloaded and has non-zero size
6. Verify the HTML report artifact is viewable
7. Verify the JSON metrics artifact parses correctly

**Expected Results**:
- CI/CD pipeline retrieves all artifacts without manual MLflow navigation
- Artifact URIs from job status are sufficient for complete retrieval
- No run_id-to-path construction logic needed in the pipeline
