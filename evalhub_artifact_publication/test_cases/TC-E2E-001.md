# TC-E2E-001: Successful evaluation with artifact URIs surfaced in job status

**Objective**: Validate the complete happy-path user journey: run evaluation, artifacts published to MLflow, URIs resolved by DefaultCallbacks, persisted by EvalHub server, and returned in job status response.

**Preconditions**:
- Full EvalHub deployment (server v0.3.0, SDK v0.1.5, MLflow v3.10.1+rhaiv.1, sidecar)
- lm-evaluation-harness adapter configured with DefaultCallbacks

**Test Steps**:
1. Submit an evaluation job via the EvalHub API with MLflow tracking enabled
2. Wait for job status to reach a terminal state
3. Verify job status is `Complete`
4. Verify `artifact_uris` contains at least one entry with `status: success`
5. Extract an artifact path from the response
6. Call GET /get-artifact?run_id={run_id}&path={artifact_path} to retrieve the artifact
7. Verify the artifact content is valid (e.g., HTML report is parseable, JSON metrics are valid)
8. Verify the artifact URI was resolved via GET /api/2.0/mlflow/artifacts/list (check sidecar proxy logs)

**Expected Results**:
- End-to-end flow completes without manual intervention
- Artifact URIs are directly usable for programmatic retrieval
- No manual path construction from run_id needed
