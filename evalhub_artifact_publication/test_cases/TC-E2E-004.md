# TC-E2E-004: Batch status retrieval for governance dashboard with mixed job outcomes

**Objective**: Validate the batch endpoint user journey: a governance dashboard queries multiple job statuses in one call, receives artifact URIs for successful jobs and failure details for partially failed jobs, and can programmatically retrieve all available reports.

**Preconditions**:
- Full EvalHub deployment (server v0.3.0, SDK v0.1.5, MLflow v3.10.1+rhaiv.1)
- Multiple completed evaluation jobs: 2 Complete, 1 CompleteWithWarnings, 1 with zero artifacts

**Test Steps**:
1. Create 4 evaluation jobs with different outcomes (2 fully successful, 1 partial failure, 1 zero artifacts)
2. Wait for all jobs to reach terminal state
3. POST to /api/v1/evaluations/jobs/batch with all 4 job IDs
4. Verify the response contains 4 job status objects
5. Verify the 2 successful jobs have status `Complete` with non-empty artifact_uris
6. Verify the partial-failure job has status `CompleteWithWarnings` with per-artifact outcomes
7. Verify the zero-artifact job has status `Complete` with empty artifact_uris list
8. For each successful artifact URI, retrieve the artifact via GET /get-artifact and verify it is valid
9. Verify artifact URIs in the batch response are sanitized (no raw S3 paths)

**Expected Results**:
- Batch response provides complete visibility into all job outcomes in one call
- Mixed statuses (Complete, CompleteWithWarnings) are correctly returned per job
- Artifact URIs are usable for programmatic retrieval without individual API calls
